# 模型调用与 GPU 实例

假设你想对一组论文摘要做分类。有两种做法，区别在于**分类程序由谁运行**。

**调用模型 API。** 把摘要和问题发给学校已经部署的模型，拿回回答。模型的调用 ID 决定请求发给哪个模型，API Key 决定你的程序能调用哪些模型。向量模型返回向量，重排模型返回候选文本的排序。选定模型后，关注一次请求的输入、输出价格和实际用量。[第一次对话](../models.md)

**申请 GPU 实例。** 如果要训练自己的分类器、安装特定依赖或使用自己的权重，先从模板选择镜像和硬件，申请一台可以登录的机器。这台机器叫**实例**。在机器上运行的 `python train.py` 是一个**作业**。可以换脚本继续使用同一台机器，直到托管时限或清理策略结束这一轮运行。[申请并连接实例](../gpu.md)

## 一台实例从申请到归还

| 你在工作台看到的阶段 | 学校或 bupt 正在做什么 | 现在可以做什么 |
| --- | --- | --- |
| 核价 | 按所选规格估算日价 | 调整配置、运行上限和到期处理 |
| 已提交、审批或排队 | 学校受理本次申请并分配资源 | 用操作 ID 查看这次申请的进度 |
| 已运行、准备 SSH | 实例已启动，控制器正在验证登录通路 | 等待实例详情出现「连接 SSH」 |
| SSH 就绪 | 登录已验证 | 进入终端、上传代码或提交后台作业 |
| 已停机、仍有预留 | 程序已停止，计算资源仍为实例保留 | 以后重启，或主动归还算力 |
| 已归还算力 | 计算预留已释放，磁盘按学校策略保留 | 核对预留状态和存储费用 |

**日价、运行时限、最终账单是三个不同的量。** 日价是规格报价；运行时限决定控制器何时开始按你的策略清理，排队和启动也占用这段时间。学校确认的预留和存储可能分别计费。实验结束时检查实际释放状态，再到[余额和账单](../usage.md)核对数据。
