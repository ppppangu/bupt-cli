# 核心概念

这一页讲两件事：该用模型 API 还是 GPU 实例，登录状态、控制器和密钥又分别对应什么。先有个印象即可，用的时候可以回来再查。

## 模型调用与 GPU 实例

假设你想对一批论文摘要做分类，有两种办法，区别在于分类程序到底由谁来运行。

调用模型 API 时，你把摘要和问题发给学校已经部署好的模型，然后拿到回答。调用 ID 决定这次请求发给哪个模型，API Key 决定你的程序能调用哪些模型；向量模型返回向量，重排模型返回候选文本的排序。选好模型后，要关注的是单次请求的输入输出价格和实际用量。参见[模型 API](models.md)。

如果你要训练自己的分类器、装特定的依赖，或者用自己的权重，就得申请一台可以登录的机器——这叫**实例**，从模板里选镜像和硬件创建。在实例上运行的 `python train.py` 算一个**作业**，可以换着脚本继续用这台机器，直到托管时限到了，或者清理策略把这轮运行收尾。参见[GPU 实例](gpu.md)。

### 一台实例从申请到归还

| 工作台里看到的阶段 | 学校或 bupt 在做什么 | 这时候能做什么 |
| --- | --- | --- |
| 核价 | 按所选规格估算日价 | 调整配置、运行上限和到期处理 |
| 已提交、审批或排队 | 学校受理本次申请并分配资源 | 用操作 ID 查看这次申请的进度 |
| 已运行、准备 SSH | 实例已启动，控制器正在验证登录通路 | 等待实例详情出现「连接 SSH」 |
| SSH 就绪 | 登录已验证 | 进入终端、上传代码或提交后台作业 |
| 已停机、仍有预留 | 程序已停止，计算资源仍为实例保留 | 以后重启，或主动归还算力 |
| 已归还算力 | 计算预留已释放，磁盘按学校策略保留 | 核对预留状态和存储费用 |

日价、运行时限和最终账单是三个不同的东西：日价只是规格报价，运行时限决定控制器从什么时候开始按策略清理（排队和启动也占这段时间），学校确认的预留和存储可能分开计费。实验结束后先确认实际的释放状态，再去[查看余额和账单](usage.md)核对数字。

## 工作区、控制器与密钥

全屏工作台里选「我的实例」，或者在 shell 里运行 `bupt compute instance`，两条路问的是同一个**控制器**。默认情况下控制器就是你电脑上的用户服务，登录会话、连接信息和操作回执都保存在**工作区**里。

关掉工作台再打开，之前提交的作业还能找到。电脑休眠时本机控制器的轮询和清理也会跟着停，恢复后才继续核对；但远端已经启动的作业不受这个影响，仍然按实例和学校平台自己的运行状态走。换终端续等时记得选回原来的控制器和 **profile**——profile 就是一组命名好的账号和连接配置，只有一套配置的话用默认值就行。

### 手里的凭据用在哪里

| 你正在做什么 | 需要什么 | 从哪里取得 |
| --- | --- | --- |
| 看学校账号、模型和配额 | 校园登录会话 | 工作台扫码，或运行 `bupt login` |
| 在工作台或用 bupt 调用模型 | 已托管、允许该模型的 Key，命令行使用 Key ID | 「模型 API → API 密钥」 |
| 在自己的 Python 或 curl 程序中调用模型 | 完整 API Key，通常由 `BUPT_API_KEY` 提供 | 导出一把已托管的 Key |
| 为实例首次配置 SSH 登录 | 实例终端密码（仅在提示需要时填写） | 在交互终端运行 `bupt auth access` |

举个例子：能扫码打开模型列表，说明校园账号可以看目录；但要真正发请求，还得在工作台里选一把这个模型能用的 Key。如果是要上传代码，走的是实例的 SSH 通路，确认 SSH 就绪就够了。
