# 工作区、登录与密钥

你可以在全屏工作台里选「我的实例」，也可以在 shell 运行 `bupt compute instance`。两种入口都向同一个**控制器**查询。默认情况下，控制器是你电脑上的用户服务，它在**工作区**里保存登录会话、连接信息和操作回执。

关闭工作台后，再次打开仍可找到已提交的作业。电脑休眠时，本机控制器的轮询和清理也会暂停，恢复后继续核对；远端已经启动的作业仍受实例和学校平台的运行状态约束。需要换终端续等时，选回原来的控制器和 **profile**。profile 是一组命名的账号与连接配置，只有一套配置时使用默认值即可。

## 手里的凭据用在哪里

| 你正在做什么                     | 需要什么                             | 从哪里取得                      |
| -------------------------- | -------------------------------- | -------------------------- |
| 看学校账号、模型和配额                | 校园登录会话                           | 工作台扫码，或运行 `bupt login`     |
| 在工作台或用 bupt 调用模型           | 已托管、允许该模型的 Key，命令行使用 Key ID      | 「模型 API → API 密钥」          |
| 在自己的 Python 或 curl 程序中调用模型 | 完整 API Key，通常由 `BUPT_API_KEY` 提供 | 导出一把已托管的 Key               |
| 为实例首次配置 SSH 登录             | 实例终端密码（仅在提示需要时填写）                | 在交互终端运行 `bupt auth access` |

例如，能扫码打开模型列表，表示校园账号可查看目录。真正发送请求前，还要在工作台选一把模型可用的 Key。若你要做的是上传代码，则走实例的 SSH 通路，先确认 SSH 就绪即可。[试用模型](../cao-zuo-zhi-nan/models/) · [连接 GPU](../cao-zuo-zhi-nan/gpu/)
